# Xiaomi Portable Photo Printer Pro: status and recovery repair

Protocol reference (EN / 中文 / 日本語): [docs/protocol](protocol/README.md).

## Scope

Targets `xiaomi.printer.ricott` / `xiaomi.printer.ricotg`. The source contract is the supplied Mi Home `com.hannto.printer` plugin 1.1.15, version code 69, `Plugin_1065830/ios/main.bundle`.

Bundle SHA-256: `95b61a95ec6e63c5330ba36a897cb41c3377a51483f3b5360e92586a3ebc2f8c`.

This is an independent implementation based on that client, not an official firmware specification. The proprietary bundle is not added to this repository. The numbered source modules and original line anchors below refer to the supplied `xiaomi_pro_api_kit` reference archive. Golden vectors are generated by the unmodified source functions; they are not claimed to be hardware captures, except for the previously existing hello fixture.

| `resume_printer` | `{}` | Resume existing device/job; no new print_job | 12407.js 282-300; 13145.js 293-325 |

Android's JSON `channel=64` is the client platform/source value, not binary frame channel 3/4. The plugin uses 576 for iOS. Existing DH and AES key derivation are retained. File data stays in 988-byte chunks with a four-byte little-endian job ID and up to three complete frames per Android write. Do not replay an ambiguous failed socket write.

`command` has a single IO owner. A valid response requires the data JSON channel, response interactive type, and an exact numeric JSON id. Events, idless objects and late replies are placed in a bounded diagnostic inbox. The official listener is looser (12407.js 793-900); this implementation deliberately does not let an uncorrelated message complete an arbitrary request. Firmware that omits JSON ids needs a separately captured, narrowly scoped compatibility strategy. Do not simply accept every idless object.

## Status model

`ProPrinterStatus` keeps raw fields. Device faults are recognized by `result.category == "error"` and `result.error`, not from task `pending` or top-level RPC code -6002. RPC errors, device errors and event.rpt_err codes occupy separate namespaces.

The verified Pro UI resume allowlist is -7103, -7110, -7111, -7112, -7114, -7201 and -7208. Source: 12332.js 248-447, 911-945; localized messages in 13484.js 934-981. In particular -7103 means no paper detected/load trouble, -7201 exhausted ribbon, and -7208 asks to install/reseat a ribbon and resume. Shared -7101/-7203 constants do not establish this Pro UI's recovery policy. Unknown faults remain visible by raw code and do not expose a resume action. A known-open cover, foreign job or malformed job reference also disables recovery.

`battery` is a band/charging enum (0-5 versus 16-21), not a percentage. A numeric, finite `battery-level` in 0..100 is displayed unscaled as a device-reported percentage candidate. Missing, string or invalid values stay unknown, never 0% or inferred from bands. The source has samples 94 and 96 (13166.js 194-235), not a hardware calibration guarantee; compare against the actual official app. Production source: 12863.js 811-839 and 12311.js 1612-1699.

Sensor bit 8 means USB connected and bit 4 means the paper tray cover is closed. Neither implies paper or ribbon availability; USB presence does not itself establish charging.

The status panel is on the Print Queue screen. It shows the time of the last successful snapshot rather than pretending the idle printer remains continuously connected. Read-only refresh is mutually exclusive with an active print session. English and Chinese resources are included; other languages use the English fallback.

## Job lifecycle and cancellation

1. Before creation, query status until idle with no job_id, matching the official manager's preflight gate. A recoverable fault can wait for user action without creating duplicate tasks.
2. Persist the side-effect boundary before print_job, and the returned device ID before sending image bytes.
3. A UI cancel enqueues an atomic intent. It does not kill the IO worker that must transmit and reconcile cancellation. Local queued items are canceled without a device command.
4. A resume click is consumed against a fresh status and the current job. Send resume_printer once; a lost acknowledgement is reconciled by polling, not blind replay. Retain the original job and image transfer history.
5. Cancel stops future batches, completes the already-written batch, sends cancel_job once, and polls job_info. Only canceled confirms cancellation. A racing finished remains a successful print. Rejection, disconnect or timeout must not fabricate a successful cancellation.
6. Only finished is success. canceled and aborted are separate terminal outcomes. pending, printing_Y/M/C/OC, home_feed, cool_down, missing results and unfamiliar states never become success by exclusion.
7. Unknown remote outcomes pause the persisted queue and disable retry/removal. After inspecting the printer and printed sheets, an explicit user confirmation plus a fresh idle/no-job snapshot can release unrelated queued work. This never automatically retries or marks the old job successful.

The raw reader buffers partial bytes across read timeouts, validates length/checksum, resynchronizes after corrupt frames and handles EOF. A bounded write watchdog closes the transport; it never repeats a possibly partially delivered batch.

## Validation and required integration gate

Dependency-free execution:

```sh
tools/verify-pro-printer-core.sh
```

This compiles real production core, crypto, status, restoration and stream classes using Kotlin/JDK (no Android SDK and no replacement test framework). Its 44 named checks include seven source-generated request frames and six file frames. It does **not** execute the JSON-dependent XiaomiPrinter session, Compose UI or Room integration.

Full gate before merge:

```sh
./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug
```

Additional JUnit tests cover scripted real-org.json sessions: wire parameter shapes, exact IDs, unsolicited messages, cancellation before/after creation and during upload, lost/rejected cancel acknowledgement, late finished, resumed original job, malformed/foreign jobs, unconfirmed outcomes and checksum recovery. The original creation/sending tests retain their coverage but reject ambiguous write replay. These full JUnit/Android checks must be executed on the modified commit; a successful build of the unmodified baseline is not evidence for this repair.

The CI uses the published `platforms;android-37.0` package with current SDK command-line tools. The release workflow only changes this SDK setup; its signing inputs, tag trigger and publication logic are unchanged. No release is requested by this repair.

## Hardware acceptance checklist

Record firmware/model and time-aligned, redacted TX/RX while checking: normal battery/USB and unplugged readings; paper absent then refilled; ribbon absent versus exhausted then replaced; cancel at creation, mid-upload and while faulted; a late finished response; disconnect and process termination after job creation. Verify there is exactly one print_job for a resumed sheet, no further file batches after cancellation takes effect, and no automatic duplicate after uncertain outcomes.

If ids, fault codes or state shapes differ, preserve the raw evidence and keep unknowns unknown. Do not enable confirm_job, OTA or shared Mint cleaning commands to work around an unresolved print fault.
